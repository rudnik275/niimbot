# CONTEXT — Бирка (наклейки для NIIMBOT)

Живой документ: словарь, границы, решения и что реально проверено. Обновлять при каждом
изменении модели или после физической проверки. Архитектурные решения — в `adr/`.

## Зачем

Дима печатает наклейки на ящики и пакетики с мелочью: болты/винты (разные головки и
резьба), светодиоды, диоды, микросхемы, крепёж, инструмент. Нужен один шаблон, чтобы
наклейка читалась с полки: **узнаваемая картинка + крупный размер/значение**, при
необходимости мелкая подпись. Печатать — из браузера по Bluetooth, без официального
приложения. Дизайн минималистичный, чёрное на белом, без лишних элементов.

Проект переписан с нуля 2026-09-16 (предыдущая попытка с Codex отвергнута: ручная
сборка PNG, печать через чужой веб-редактор, брак на первом отпечатке).

## Словарь

| Термин | Значение |
| --- | --- |
| **Наклейка** (`LabelSpec`) | что напечатано на одном стикере: пиктограмма, крупный текст, подпись. Стиль не хранится — он один для всех |
| **Формат** (`MediaProfile`) | физическая лента: ширина × высота одной наклейки, сколько наклеек в **единице подачи**, тип (с зазорами / сплошная / чёрная метка), привязанные RFID-штрихкоды |
| **Страница** | единица подачи принтера — то, что он проматывает от зазора до зазора. Для парной ленты страница = две наклейки. Печатается только целиком |
| **Слот** | место одной наклейки внутри страницы (сверху вниз по подаче) |
| **Пиктограмма** (`IconDef`/`IconArt`) | векторная картинка в юнитах (высота 100), контуры одной толщины; может иметь **параметры** (болт: головка, резьба, шлиц) |
| **Раскладка** (`LabelLayout`) | результат чистой функции `layoutLabel`: где иконка, разделитель, текст; не знает про canvas |
| **Точка** | пиксель принтера, 1/8 мм при 203 dpi |

## Железо и лента (проверено)

- Принтер **NIIMBOT B1**: 203 dpi, головка 384 точки (48 мм), плотность 1–5 (по умолчанию 3),
  направление печати `top` (ширина холста = поперёк головки), печать через задачу `B1`
  niimbluelib. Подтверждено первым тестом Codex 2026-09-14: связь по Web Bluetooth,
  ответ `In_PrintEnd`.
- Лента **T40×15MM/2R**, штрихкод RFID `6971501227736`: наклейки 40×15 мм, **две вплотную по
  подаче, зазор только между парами**. Подтверждено фото отпечатка (напечаталась
  только верхняя половина, нижняя осталась пустой). Страница = 320×240 точек.
- RFID на B1 читается (`RfidInfo`: штрихкод, всего/использовано). Данных о размере
  бумаги (`PaperInfo`) в установленной niimbluelib 0.46 нет; размер берётся из профиля.

## Что НЕ проверено (на 2026-09-16)

- **Ни одного отпечатка новым приложением ещё не было.** Проверить первой же печатью:
  1) обе половины пары заполнены; 2) масштаб 1:1 (линейка: текст 40 мм шириной); 3) центровка —
  при сдвиге подобрать X/Y по тесту калибровки; 4) толщина линий пиктограмм (сейчас ≈0,5 мм)
  и порог 150 — при «жирности» снизить плотность до 2 или порог до 130.
- **Живого Bluetooth-сеанса не было ни разу**: ни диалога выбора в Electron, ни запроса
  разрешения macOS, ни автовыбора прошлого принтера в окне `BlePicker`.
- Быстрое переподключение через `getDevices()` (браузерная ветка того же кода).
- Форматы кроме парного 40×15.
- Мелкая деталь новых схемных знаков в 1 бит: `bridge` (четыре диода в ромбе), `optocoupler`
  (два знака и стрелки в корпусе), `breadboard` (двадцать точек). Проверены только на превью
  при высоте 90 px; если на отпечатке сливаются — упростить, а не утоньшать линию.

## Открытые вопросы

- **«Латунные шайбы для 3D-печати»** (просьба 2026-09-16) реализованы как *резьбовые втулки
  под запрессовку* — пиктограмма `insert`, «Втулка латунная (3D-печать)». Если имелись в виду
  именно шайбы, нужен отдельный знак. Спросить при следующей правке библиотеки.
- В «Электронике» стало 59 знаков — сетка выбора (3 колонки, `max-height: 340px`) прокручивается
  на два десятка рядов. Пока спасает поиск: у каждого знака ключевые слова по-русски и по
  маркировке (`симистор`, `bt136`, `7805`, `ky-040`). Если станет неудобно — делить категорию
  на подгруппы, а не резать библиотеку.

## Решения (кратко; подробно в adr/)

1. Браузерное приложение на niimbluelib по Web Bluetooth, никаких Python-скриптов и
   официального клиента ([ADR-0001](adr/0001-web-bluetooth-app.md)).
2. Страница = единица подачи; парная лента моделируется слотами ([ADR-0002](adr/0002-page-is-feed-unit.md)).
3. Рендер попиксельно точный: canvas в точках принтера, бинаризация до кодирования,
   превью без сглаживания ([ADR-0003](adr/0003-pixel-exact-rendering.md)).
4. Пиктограммы — собственная векторная библиотека с единой толщиной линии и параметрическим
   болтом, а не генерация картинок ([ADR-0004](adr/0004-vector-icon-library.md)).
5. Эталон болта (`reference/bolt-reference-approved.png`) — ориентир композиции:
   контурный болт слева, вертикальный разделитель, крупный размер, подпись. **Стиль один и
   фиксированный** (решение пользователя 2026-09-16): шрифт Golos Text, без рамки, без
   линий у подписи, никаких переключателей стиля — «одна в одном стиле, другая в другом,
   такого не будет». Рамка и линии с эталона намеренно не переносятся.
6. Раскладка «общее — отдельно, личное — отдельно»: принтер, лента и формат в верхней
   полосе, печать под превью; у каждой наклейки пары свой полный сайдбар (левый — верхняя,
   правый — нижняя) с текстом, выбором пиктограммы, её параметрами и недавними. Никаких
   переключений «какую наклейку редактируем», превью — только для просмотра.
7. Настольная оболочка — Electron с собственным окном выбора Bluetooth-устройства
   ([ADR-0005](adr/0005-electron-shell.md)); веб-версия остаётся тем же кодом.

## Предпочтения пользователя

- Крупный размер + узнаваемая картинка важнее всего; подписи мелкие и необязательные.
- Практически всегда печатаются сразу две наклейки (пара) — интерфейс исходит из этого.
- Хочет уметь определять вставленную ленту (RFID) и работать с другими форматами.
- Идея на потом: еда — картинка продукта, название, срок/дата (даты только от пользователя).

## Хранилище

Всё состояние в `localStorage` ключ `birka.v1`: наклейки, формат, свои форматы, привязки
штрихкодов, настройки печати, библиотека. Имя последнего принтера — `birka.lastDevice`.
