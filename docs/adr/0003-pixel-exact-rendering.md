# ADR-0003. Попиксельно точный рендер: canvas в точках принтера, бинаризация до кодирования

Дата: 2026-09-16 · Статус: принято

## Контекст

Кодировщик niimbluelib (`ImageEncoder`) считает чёрным любой пиксель, кроме `#ffffff`.
Любое сглаживание (антиалиасинг текста, серые края линий) превращается в чёрные ореолы —
«винт сливается, края некачественные» на первом отпечатке. Тогда же чужой редактор
масштабировал картинку до 6/7.

## Решение

1. Страница рисуется на canvas размером ровно `cols × rows` точек принтера (8 точек/мм),
   без масштабирования на этапе печати.
2. Раскладка (`render/layout.ts`) — чистая функция с внедрённым измерителем текста;
   все координаты целые, линии нечётной толщины смещаются на 0,5 px, чтобы ложиться на
   целые пиксели.
3. После отрисовки страница бинаризуется по яркости (`render/raster.ts`, порог 150 по
   умолчанию, регулируется в калибровке) — в кодировщик уходит строго чёрно-белый битмап.
4. Превью показывает тот же canvas, увеличенный CSS без сглаживания (`image-rendering:
   pixelated`), с миллиметровыми линейками. Кнопка PNG выгружает его как есть.
5. Сдвиги X/Y (в точках) применяются ко всем слотам; тест калибровки печатает рамку в 1 мм
   от края и центр — по нему подбирается сдвиг под конкретный принтер.
6. Для принтеров с направлением `left` страница поворачивается на 90° против часовой,
   чтобы поворот библиотеки по часовой вернул исходную ориентацию (проверено тестом
   против самого кодировщика).

## Последствия

- Что на экране — то на бумаге; расхождения могут быть только физическими (люфт
  позиционирования, растекание при высокой плотности) и лечатся сдвигом/порогом/плотностью.
- Шрифты для наклейки бандлятся (Golos Text, JetBrains Mono) и ждут загрузки перед
  рендером — иначе первый рендер уйдёт запасным шрифтом.
